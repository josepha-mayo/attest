Attest

Tamper-evident visit records for home services, built on the Ring Partner API — what the devices observed, what the worker reported, what a human concluded. Records, not verdicts.

"He said / she said" disputes stop being memory contests: every observation, statement, and conclusion is a separate Ed25519-signed receipt on a hash-chained ledger — disagreements stay on the record, flagged and verbatim, because the record never adjudicates. And the pack you're about to verify carries its own verifier, so nobody has to trust this site either.

The regulated version of this gap is already a documented failure: New York's comptroller found $14.5B paid against 82M personal-care visits with no matching record, and Ohio's auditor found 34% of EVV entries manually adjusted — invisibly. Editable records are the problem; Attest makes them tamper-evident.

Ring surface called at runtime: signed webhooks · Event History · media & snapshots (regional redirect handled) · devices/capabilities · app-integrations · subscriptions · WHEP live view. Track fit: business systems + caretaking, with accessibility carried through the household view and doorstep QR flow.

The fork nobody can hide


The transparency log's whole point: even we can't rewrite history. One
issuer key, two histories — a witness pins one tree head, a monitor pins the
other. Neither side can tell alone; together they prove the fork, and the catch
itself is signed as a monitor_observation receipt committed inside a
signed tree head. Verify the caught
fork in your browser — the evidence doc's checkpoint signature, inclusion
proofs, and embedded observation all check out. Reproduce it:
attest split-demo fabricates the whole scenario in scratch space and
emits the same evidence document.



Five AWS touchpoints — three verified live


    

  • Lambda verified live — attest-verify-pack
re-verifies a posted pack in AWS using the project's pinned verifier, never the
pack's embedded script — data and code come from different parties:
    • 




  

  
$ aws lambda invoke --function-name attest-verify-pack \
    --payload fileb://pack.json out.json
  {"ok": true} — 2 visit records, 43 receipts proven inside the log
  (transcript of the 2026-09-18 run — the current pack carries 9)
$ # doctor one byte in a signed payload, invoke again
  {"ok": false} — payload hash mismatch (payload was altered)
  the function catches exactly what the local verifiers catch




    

  • KMS verified live — the Ed25519 signing key
is envelope-encrypted under a KMS data key (AES-256-GCM + encryption context); every
unwrap is a CloudTrail-audited Decrypt, verified end-to-end on a real CMK.
    • 

  • S3 verified live — attest anchor
--publish uploads signed checkpoints to a versioned, public-access-blocked
bucket with the file sha256 stamped into object metadata — a checkpoint outside
the deployment's control.
    • 

  • Bedrock Converse labeled fallback — writes
per-record narrative summaries with provenance labels; the account's on-demand
quota is zero, so every model call authenticates then throttles — and the record
labels the deterministic fallback as its true source instead of pretending.
    • 

  • Strands agent labeled fallback — the weekly
triage brief reads the ledger through real read-only tools; same quota wall, same
honest labeling (strands-agent vs deterministic + reason).
    • 



The fallback path is itself verified against real AWS failure modes —
expired aws login creds surface as LoginRefreshRequired,
quota as ThrottlingException — which is the designed behavior, not a
mock. An honest FAIL on the label beats a fake PASS.

What verification proves — and what it doesn't




A green verdict means


    

  • Every signature is valid under the pinned issuer key.
    • 

  • No record was added, dropped, or altered since signing.
    • 

  • The receipts are committed in the signed transparency-log head the pack carries.
    • 

  • Redacted media was withheld by policy — its signed digests still match the manifest.
    • 



It does not mean


    

  • That the worker physically attended — camera activity is an observation, not attendance.
    • 

  • That absence of events means absence — silence isn't absence.
    • 

  • That the issuer is honest — a signature proves integrity under a key, not truth.
That's why witness cosigning and the live-log cross-check exist.
    • 






What's inside the sample pack


The bundled sample-pack.zip is a real export from the
simulated Alvarez residence deployment — media withheld by redaction policy,
signed SHA-256 digests preserved. It exercises the hard parts, not just the happy path:


    

  • a signing-key rotation mid-history: the pack names both issuer keys —
  the rotated-away key, its signed adoption, and the revocation receipt that retires it;
    • 

  • receipts on both sides of the pivot, verified under different keys;
    • 

  • a suspect-window annotation — the window signed while the old key was
  compromised inherits doubt, explicitly;
    • 

  • verifier_manifest.json pinning the verifier tooling's own hashes —
  the pack defends against a hostile verifier shipped inside itself;
    • 

  • log_checkpoint.json: a signed RFC 6962-style Merkle tree head with
  inclusion proofs — the receipts are committed in a transparency log, and the verifier's
  cross-check can prove the deployment still serves the same head to everyone;
    • 

  • a witness cosignature anchored in the witness's own
  independent published log — the attestation is publicly committed the moment
  it's served;
    • 

  • and outside the zip, one click over: divergence-checkpoint.json
  — signed monitor evidence of a caught log fork (the split-demo
  scenario), verified by the same page.
    • 



The embedded index.html is a record browser, not a file listing:
worker, household, and coordinator voices rendered separately from the signed
payload (two conflicting household accounts are flagged, never merged),
per-visit signed anchors and deep links, a plain-language tab that prints clean,
viewer-local times with the signed UTC literal on hover, and a six-element
Cures Act crosswalk — the federal EVV statute mapped to evidence fields,
labelled as corroboration, never as submission.



Pin the issuer out-of-band. This site also publishes the demo
deployment's signed issuer document:
attest-issuer.json
— the same document a live deployment serves at its origin well-known.
Fetch it over an independent transport, then verify against it instead of the
pack's self-declared key: attest verify pack.zip
--issuer-url attest-issuer.json (or --issuer attest-issuer.json
on the stdlib script inside the zip). The signed lifecycle receipts extend
trust both directions across the rotation — the pack and its trust anchor
arrive by different surfaces, which is the whole point of pinning. Or see it
one-click: verify the sample pack
pinned to the issuer document this site serves. And the verifier page
itself is pinned: every pack's signed verifier_manifest.json
byte-pins verify.html — sha256 the hosted page and
compare it to the pin inside any pack; the checker can't be swapped behind
your back.
