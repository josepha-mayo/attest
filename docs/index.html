  • Threat model and limits

The limit: valid signatures do not establish physical presence, service delivery, a person's identity, or the truth of a statement. This is a prototype, not an EVV system.

How is this different from Ring Event History?

Ring provides device events. Attest connects observations to a scheduled visit, keeps people's statements separate, and exports a signed record with its own verifier.

The recipient can check the exported evidence without trusting Attest's server to describe it accurately. That proves integrity within the stated trust boundary, not that an observation happened in the physical world.

Ring, AWS, and what this demo actually runs

This page and verifier run in your browser. Product pages are static snapshots; they do not call a live Attest backend. The sample visit is simulated with ring-sandbox, an independent client and emulator of the documented Ring API.

The project's recorded AWS checks cover Lambda pack verification, KMS envelope encryption, and S3 checkpoint publishing. They are prior integration evidence, not services invoked by this page.

Bedrock Converse and the Strands agent have labeled deterministic fallbacks because the demo account's on-demand model quota is zero. A fallback is not a successful model inference.
